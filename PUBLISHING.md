# Publish to GitHub

Repository: `https://github.com/Chiesu/gs-capture-dome`

## Repository metadata

- **Name:** `gs-capture-dome`
- **Visibility:** Public
- **Description:** Blender multi-camera capture rigs for Gaussian Splatting experiments, with orbit/look-around modes, batch rendering and camera transform export.
- **Topics:** `blender`, `blender-addon`, `gaussian-splatting`, `photogrammetry`, `camera-rig`, `synthetic-data`, `open-source`
- **README / License / gitignore on GitHub creation:** Leave unchecked/None. All three files are already included in the source archive.

## 1. Upload the repository source

1. Download **`gs-capture-dome-v0.5.0-github-source.zip`** and extract it.
2. Create the new public repository **`gs-capture-dome`** on GitHub.
3. Open the *inside* of the extracted source folder and select **all contents**, including the hidden `.github` folder, `README.md`, `LICENSE`, `blender_manifest.toml`, `__init__.py`, `gs_capture_dome.py`, `docs/`, `scripts/` and `tests/`.
4. Upload those items to the **root of the new repository**, not into another `gs-capture-dome` subfolder. On Mac, `Cmd + Shift + .` in Finder shows hidden files.
5. Commit as `Initial public release: GS Capture Dome v0.5.0`.

If the GitHub browser uploader cannot preserve nested folders or hidden files, clone the empty repository with **GitHub Desktop**, copy the archive contents into the cloned folder (not another nested folder), then Commit and Push. This is usually the simplest reliable way to upload the complete tree.

## 2. Create a release

1. Open the repository's **Releases** section > **Draft a new release**.
2. Tag: **`v0.5.0`** (create the tag from `main`).
3. Title: **`GS Capture Dome v0.5.0`**.
4. Description: paste **`RELEASE_NOTES.md`**.
5. Attach **`gs_capture_dome-0.5.0.zip`** as the downloadable release asset. You can also attach `SHA256SUMS.txt`.
6. Select **Set as latest release** and Publish. Do not upload the source-repository ZIP as the installable Blender extension.

The README's `releases/latest` link becomes valid as soon as this release is published.

## 3. Verify

- GitHub repo root contains `blender_manifest.toml`, `__init__.py`, `gs_capture_dome.py`, `README.md` and `LICENSE`.
- The release page contains the explicitly uploaded `gs_capture_dome-0.5.0.zip` asset, not just GitHub's autogenerated **Source code** archives.
- Download that ZIP and verify that `blender_manifest.toml` and `__init__.py` sit at ZIP root (not inside a nested folder).
- Install the ZIP in Blender and run the small-scale tests from `docs/TESTING.md` before describing the release as Blender-tested.
- Once verified, add 2-3 real screenshots/GIFs from Blender to improve the repo presentation (see `docs/PUBLISHING_ASSETS.md`).
